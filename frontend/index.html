Contained by design

Every risky action runs in a throwaway sandbox. Nothing it does can touch the host.

  • No networkSandboxes run with networking disabled. Untrusted code cannot call out or exfiltrate data.
  • Read-only filesystemThe container root is read-only; only a small size-limited temp area is writable.
  • Unprivileged userCode runs as a non-root user with all Linux capabilities dropped and no-new-privileges enforced.
  • Hard resource limitsCPU, memory and process counts are capped per container, so fork bombs and memory bombs are stopped.
  • No secrets insideAPI keys never enter a sandbox. Any credentials the code can find are fake honeypots that we monitor.
  • Destroyed after every taskEach run uses a one-time container that is removed afterwards, and we verify it is really gone.
  • Signed audit receiptsEvery sandbox run produces an HMAC-signed receipt with command hash, output hash, policy decision and cleanup status.
